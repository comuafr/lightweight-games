# WORKFLOW.md — Per-game procedure

Follow these steps in order for each game. All games live in ONE monorepo, each
under `games/<slug>/` (e.g. `games/block-puzzle`, `games/snake`). A game is a
self-contained Gradle project that shares the repo-root wrapper and the root CI.
Run its Gradle tasks from the repo root with `./gradlew -p games/<slug> <task>`.

## 0. Plan
- Pick a **generic, non-trademarked** name and a package id `com.lightweight.<slug>`.
- Write a short design note: core mechanics, win/lose conditions, controls,
  scoring. Identify the minimal feature set that makes the game "complete".
- Confirm the concept is public-domain / generic. If unsure, flag in REVIEW.md.

## 1. Scaffold
Run `python3 new_game.py <slug> "<App Name>" <pkgsuffix>` (copies `templates/`
into `games/<slug>/` and substitutes placeholders). The structure:
```
games/<slug>/
  settings.gradle.kts
  build.gradle.kts
  gradle.properties
  .gitignore
  LICENSE
  README.md
  REVIEW.md
  STORE_LISTING.md
  tools/gen_sounds.py
  app/
    build.gradle.kts
    proguard-rules.pro
    src/main/AndroidManifest.xml
    src/main/res/values/styles.xml
    src/main/res/mipmap-anydpi-v26/ic.xml
    src/main/res/drawable/ic_fg.xml
    src/main/res/raw/            (generated by gen_sounds.py)
    src/main/java/com/lightweight/<slug>/
      Game.kt        pure logic, NO Android imports
      GameView.kt    SurfaceView + loop + input + render
      Sound.kt       SoundPool wrapper
      MainActivity.kt
    src/test/java/com/lightweight/<slug>/
      GameTest.kt    JUnit tests of Game.kt on the JVM
```
Substitute `<slug>`, package name, app name, and colors throughout.

## 2. Implement game logic (`Game.kt`)
- Pure Kotlin, no Android imports whatsoever (enforced by a CI grep check).
- Deterministic and unit-testable. Inject randomness via a `() -> Double` so
  tests can seed it.
- Keep state in primitive arrays where possible; avoid per-frame allocation.

## 3. Write JUnit tests (`GameTest.kt`)
- Cover the rules that are easy to get wrong: collision/bounds, scoring,
  win/lose detection, any RNG fairness invariant, edge cases at borders.
- Tests must run with `./gradlew -p games/<slug> test` and pass.

## 4. Implement rendering & input (`GameView.kt`)
- `SurfaceView` + `Canvas`, game loop on a dedicated thread, ~60 fps with sleep.
- Reuse a single `Paint`. No allocation in `draw()`/`step()`.
- Touch controls appropriate to the game; document them in README.

## 5. Sound (`tools/gen_sounds.py` -> `res/raw`)
- Generate 8-bit PCM mono WAVs at 11025 Hz by synthesis. Keep them tiny.
- Wire them through `Sound.kt` (SoundPool). Release in `surfaceDestroyed`.

## 6. Branding
- Generate an app icon as an adaptive vector (mipmap-anydpi-v26 + drawable),
  no PNG bitmaps in the APK.
- Produce a 512x512 PNG of the icon for the store listing only (kept in repo
  under `branding/`, not in the app resources).

## 7. Build & measure (all from the repo root)
- `./gradlew -p games/<slug> test` must pass.
- `./gradlew -p games/<slug> lint` must pass.
- `./gradlew -p games/<slug> bundleRelease assembleRelease` must succeed.
- Record the real APK size; fail if > 1.5 MB. (CI also enforces this.)

## 8. Docs
- Fill README.md, STORE_LISTING.md (short <=80 chars, full <=4000 chars),
  and REVIEW.md (human checklist: name/trademark, measured size, anything
  flagged).

## 9. Git (single monorepo)
- Stage and commit the new `games/<slug>/` on a branch; open a PR into `main`.
  Do NOT create a separate per-game repo.
- The root `.gitignore` already excludes `build/`, `.gradle/`,
  `local.properties`, and keystores (`*.jks`, `*.keystore`). NEVER commit
  signing keys. The shared `gradle/wrapper/gradle-wrapper.jar` IS committed.
- CI auto-discovers `games/*`, so the new game is built without any workflow edit.

## 10. Hand off
- Output a one-paragraph summary and the REVIEW.md contents so the human knows
  exactly what to verify before publishing.
